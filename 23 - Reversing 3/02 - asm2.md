## Descripción

What does asm2(0x4,0x29) return? Submit the flag as a hexadecimal value (starting with '0x'). NOTE: Your submission for this question will NOT be in the normal flag format. [Source](https://challenge-files.cylabacademy.net/library/970db6f9114bc04f46705c691cb4b3c3f2a9631904e972a84e9ce8d29714d3c8/test.S)

## Solución

1. Se abrió el apartado **Source** del reto para obtener el código ensamblador de la función `asm2`.

2. Se identificaron los argumentos recibidos por la función:
    - Primer argumento: `0x4`.
    - Segundo argumento: `0x29`.

3. Se observó que el programa guardaba los argumentos en variables locales:
    ```asm
    mov eax,DWORD PTR [ebp+0xc]
    mov DWORD PTR [ebp-0x4],eax
    
    mov eax,DWORD PTR [ebp+0x8]
    mov DWORD PTR [ebp-0x8],eax
    ```
    Los valores iniciales fueron:
    - `[ebp-0x4] = 0x29` (41 decimal).
    - `[ebp-0x8] = 0x4` (4 decimal).

3. Se analizaron las instrucciones del ciclo:
    ```asm
    add DWORD PTR [ebp-0x4],0x1
    add DWORD PTR [ebp-0x8],0x94
    ```
    En cada repetición, la primera variable aumentaba en 1 y la segunda en `0x94` (148 decimal).

4. Se identificó la condición que controlaba el ciclo:
    ```asm
    cmp DWORD PTR [ebp-0x8],0x38f0
    jle 0x1191 <asm2+20>
    ```
    El ciclo continuaba mientras la segunda variable fuera menor o igual a `0x38f0` (14576 decimal).

5. Se calcularon las repeticiones:
    ```text
    4 + (148 × 98) = 14508
    4 + (148 × 99) = 14656
    ```
    Como 14508 todavía cumplía la condición y 14656 la superaba, el ciclo se ejecutó 99 veces.

6. Se calculó el valor final de la primera variable:
    ```text
    41 + 99 = 140
    ```
    Finalmente, se convirtió el resultado decimal a hexadecimal:
    ```text
    140 decimal = 0x8C
    ```

7. Se comprobó que la instrucción `mov eax,DWORD PTR [ebp-0x4]` colocaba el resultado en el registro `eax`, que posteriormente se devolvía mediante `ret`.
```
0x8C
```
